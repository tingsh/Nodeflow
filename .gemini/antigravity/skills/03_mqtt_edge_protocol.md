# Skill: MQTT & Edge Protocol Contract

## Metadata
- **ID:** 03_mqtt_edge_protocol
- **Description:** The definitive technical contract for bidirectional communication between Nodeflow Cloud and the Edge Gateways.
- **Scope:** Use this skill when modifying MQTT consumers, publishers, gateway provisioning logic, or RPC command structures.

---

## 1. Topic Structure & Payloads

### Inbound (Edge → Cloud)
- **Telemetry:** `v1/gateway/telemetry`
  - Payload: `{"ts": 1625097600000, "values": {"temperature": 25.4, "humidity": 60}}`
  - Note: Timestamp is in milliseconds.
- **Attributes:** `v1/gateway/attributes`
  - Used for heartbeat, firmware version, and local IP reporting.
- **RPC Response:** `v1/gateway/rpc/response`
  - Payload: `{"id": "uuid", "success": true, "result": "motor_started"}`

### Outbound (Cloud → Edge)
- **Config Push:** `v1/gateway/{serial}/config`
  - Pushes Modbus/OPC-UA connector configurations to the gateway.
- **RPC Request:** `v1/gateway/{serial}/rpc/request`
  - Commands like `reboot`, `restart_connector`, or `write_register`.
- **Attributes Request:** `v1/gateway/{serial}/attributes/request`
  - Cloud-to-gateway attribute sync.

## 2. Gateway Provisioning Workflow
1. **Registration:** User creates a Gateway in Nodeflow Cloud.
2. **Claim Code:** Cloud generates a unique, one-time claim code.
3. **Edge Discovery:** The edge gateway software reports its serial number.
4. **Claiming:** User enters the claim code in the local Edge UI or via the Cloud.
5. **Credentials:** Cloud generates MQTT username/password (scoped to the gateway's serial number).
6. **ACL Enforcement:** Mosquitto Dynamic Security (DynSec) is updated to restrict the gateway to its specific topics.

## 3. RPC Command Schema
Commands must be tracked in the `RpcCommand` model for auditability.
- **Request:** `{"method": "toggle_switch", "params": {"state": "on"}, "id": "tx_123"}`
- **Success Criteria:** Gateway must acknowledge within the timeout period (default 30s) on the response topic.

## 4. Security & TLS
- **Port:** 8883 (MQTTS).
- **Encryption:** One-way TLS (Server CA validation) is the standard.
- **Enterprise:** Support for Mutual TLS (mTLS) where each gateway has a unique client certificate generated by Nodeflow's internal CA.
